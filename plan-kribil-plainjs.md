# План разработки «Крибил» (Cue Crew) — чистый JavaScript

> Финальный план-артефакт: самодостаточная спецификация для форка или повторной
> реализации без переписки в чате. Описывает архитектуру, контракты, алгоритмы и
> решения, которые реализованы в этом репозитории (`index.html`, `js/`, `css/`,
> `tests/`). Это не лог разработки.

---

## 1. Игра

На бильярдном столе один **прицельный шар 1** (object ball). Команда из
**4 игроков**, у каждого свой **биток** (cue ball). Кием можно бить только по
биткам; шар 1 двигается лишь через столкновения.

Шар 1 нужно провести через **4 контрольные точки** строго по порядку.
Быстрее — лучше. Удар описывается тройкой `(t, angle, power)`:

- `t` — момент удара в секундах от начала партии;
- `angle` — направление импульса;
- `power` — скорость импульса битка, м/с (ограничена `maxPower`).

Две модели расстановки битков:

- **locked («замок»)** — позиции всех битков фиксируются вместе с маршрутом до
  начала игры; решатель подбирает только удары;
- **free («свободно»)** — маршрут точек фиксируется, а битки можно ставить куда
  угодно; решатель выбирает и позиции, и удары (время на установку учитывается:
  свободный биток стреляет только после прихода шара 1 в нужную зону).

Два режима приложения:

- **планировщик** — расчёт траекторий в статике: перемотка времени, ручная
  правка ударов и расстановки, кнопка авторешателя;
- **вживую** — человек играет за одного из 4, остальные трое — боты с разными
  стратегиями (240 Гц физика в реальном времени).

### Требования к интерфейсу

- Виден **полный** time-colored след всех шаров со всеми столкновениями;
  длина конечна (разумный кэп, чтобы не зависнуть).
- Слайдер времени (scrubber) и интерактивная шкала: моменты ударов, интервалы
  прохождения точек, соударения.
- Режимы курсора: «тащить» (шары, точки) и «целиться» (угол/сила/время удара,
  радиус контрольной точки).
- Опции: массы шара 1 и битков, трение (включая 0 — лёд), упругость шаров и
  бортов, радиус шаров, горизонт времени, максимум силы.
- **Прецизионные слайдеры** угла/силы/времени: относительные, логарифмические
  (см. §10).
- Копирование/вставка всей установки JSON-строкой.
- Рекорды времени на маршрут (localStorage).
- Юнит-тесты: биток попадает по шару 1; шар проходит точку; считается общее
  время финиша.

## 2. Рантайм и стиль (из AGENTS.md)

- **Никакого TypeScript, сборки и модулей.** Каждый файл — classic `<script>`,
  приложение открывается прямо по `file://`.
- Общее пространство имён `window.Kribil` (в ноде — `module.exports`). Канон:

  ```js
  "use strict";
  (function (global, factory) {
  	const K = global.Kribil ?? (global.Kribil = {});
  	factory(K);
  	if (typeof module !== "undefined" && module.exports) module.exports = K;
  })(typeof globalThis !== "undefined" ? globalThis : this, function (K) {
  	if (typeof require === "function") require("./core.js");
  	// ...
  });
  ```

- Сторонние библиотеки — только вендоренные локально, никаких CDN. Их нет:
  весь стек — DOM API + canvas 2D.
- Отступ — один таб, LF. Ранний выход вместо глубоких вложений. Без дублей.
- В горячих путях (шаг симуляции, кадр рендера) не аллоцировать объекты/массивы
  и не складывать строки: типизированные массивы и scratch-буферы, мутация на
  месте.
- Комментарии только про «почему», имена говорят сами. Без легаси и защиты от
  несуществующих кейсов.

### Порядок загрузки (зависимости по require в ноде)

```
core → geo → physics → traj → levels → simulate → bots → optimizer → realtime
                                                                 render → app
```

## 4. Модель физики

Стол: `TABLE = { w: 2.4, h: 1.2, rail: 0.11 }` (метры, игровое сукно внутри
бортов; рендер добавляет рейлы по краям).

Параметры по умолчанию:

```
friction 0.55 (линейное затухание скорости в м/с за секунду качения; 0 — лёд)
restitution 1.0   — упругость шар-шар
cushion 0.92      — упругость отбоя от борта
stopEps 0.02      — порог полной остановки
ballRadius 0.03
objectMass 1, cueMass 1
```

Тело: `{ kind: 'object'|'cue', owner, x, y, vx, vy, r, m, idx }`.
Импульс удара: `applyImpulse(b, a, p)` → `v += p/m · (cos a, sin a)`.

Интегратор в `stepBodies(balls, h, params, table, events, t)`:

1. полупозиции/интеграция трения: скорость уменьшается на `friction·h`,
   направление сохраняется; около нуля тело встаёт (`stopEps`);
2. перебор пар шаров — импульсное разрешение по нормали с `restitution`,
   микросдвиг наложения, событие `contact`;
3. отражение от 4 бортов с коэффициентом `cushion` и микросдвигом,
   событие `cushion`;
4. события ограничены кольцом `MAX_EVENTS`.

**Имена событий важны:** `contact`, `cushion` (не «rail»), `shot`,
`checkpoint`, `finish`, `rest`.

Симуляция планировщика использует вложенный шаг: видимые кадры `fps=60…120`,
внутри каждого кадра `sub=3…4` физических подшага — удары и проходы точек
детектируются на подшаге, иначе на 60 Гц шары могут «перепрыгнуть» контакт.

### Прохождение точки

Точка — круг `{id, x, y, r}`. Засчитывается, когда центр шара 1 оказался
внутри круга в момент, когда все предыдущие точки уже пройдены (строгий
порядок). Пишутся:

- `passed[k]` — момент зачёта (или `NaN`);
- `winEnter[k]`, `windows[k] = [tIn, tOut]` — интервал нахождения в круге
  (для шкалы времени); вход и выход без зачёта сбрасывают вход;
- `nearest[k]` — ближайшая дистанция для непройденных (направляющий член для
  оптимизатора, семплируется на частоте кадров, не на подшаге).

Финиш — момент прохождения последней точки; симуляция держит
`holdAfterFinish = 0.4 с` и останавливается, когда вся энергия близка к нулю
и все удары применены (после 0.25 с покоя), либо на жёстком лимите
`(maxTime + hold + 0.6)·fps` кадров.

## 5. Траектории (`Traj`)

Плоские `Float64Array`: `time[cap]`, `pos[cap*nb*2]`, `vel[...]`, где
`nb = 5` (шар 1 + четыре битка). `ensure()` удваивает ёмкость (512 кадров
старт в живом режиме, до 4096 в планировщике).

- `push(t, balls)` — снапшот;
- `at(t, b)` → `{x, y}` с линейной интерполяцией между кадрами (используется
  скраббером, стрелками ударов, рендером);
- `frameAt(t)` → `{i0, f}`;
- `x(i,b)/y(i,b)/speed(i,b)` — доступ без аллокаций.

## 6. Контракт `runSim(cfg)`

```js
cfg = {
  table, params, object:{x,y}, cues:[{x,y}×4], checkpoints:[{id,x,y,r}×4],
  shots:[{id, player, t, angle, power}],
  maxTime, maxPower,
  placement: 'locked'|'free', timeMode: bool,
  fps, sub, record = true, trackNearest = true, holdAfterFinish,
}
```

Удар применяется к телу битка `owner === shot.player` в текущей позиции
(биток к моменту удара мог укатиться от собственного предыдущего удара).

Возвращает:

```js
{ frames, bodies, passed, nearest, windows, firstContact, contacts, touches,
  finishAt, duration, events, maxTime, solved }
```

`solved === passed.every(finite)`.

`planCost(res, {guide=26, miss=1500})`: сумма времён leg'ов + направляющий
член по `nearest` (×26) + 1500 за каждую непройденную точку. Направляющий
член критичен: у поиска всегда есть конечный гладкий градиент «куда
улучшать», даже когда точка ещё не задета.

## 7. Решатель

Задача не решается аналитически: многотельные отскоки, трение и тайминги
делают карту решения разрывной. Используется локальный поиск с несколькими
механизмами побега из локальных минимумов.

### 7.1. Представление состояния

`state = { shots: [...], cues: [...] }`. Оценка — `evaluate(cfg, state)` →
`{cost, res}` (один прогон `runSim`); каждый кандидат обязан использовать
**один** объект результата (двойной вызов cost даёт устаревший `res`).
Штраф за взаимное наложение шаров в свободной расстановке: `400·overlap²`.

### 7.2. Последовательная конструкция leg'ов (`legSearch`)

Нога k — доведение шара 1 от точки k−1 до точки k. Из прогона-прототипа
(`legSim`, запись кадров) берётся `tArrive = passed[k−1]` и позиция/скорость
шара в этот момент.

- Точка контакта («ghost ball») — `contactPoint(src, dir, 2r)`: шар 1 в точке
  касания, биток бьёт в неё.
- **free**: берётся ближайший ещё не использованный биток и ставится рядом с
  ghost по касательной/спирали; удар статично планируется на `tArrive + 0.08`
  (время на установку);
- **locked**: биток не двигается, выбор идёт по shootability-оценке маршрута
  `routeOf(p)`:
  - прямой удар допускается только при «попутности» нормали контакта
    `fwd > 0.45`; счёт `1000 + fwd·200 − d·10`;
  - иначе одно-бортный банк (`bankShot`), счёт `500 − len·30`;
  - повторно биток используется, только если он уже стоит/покоится;
  - задел по силе для банка — ×1.25.
- Сила под время/дистанцию: `timedPower`, `powerFor`; для locked-ног
  время и сила связаны через синхронный τ-sweep (момент удара
  `τ = tArrive − tTravel`), крутить их независимо нельзя.
- Фолбэки конструктора: веер из 40 углов, 60 сидированных рестартов,
  полный 360°-перебор.

### 7.3. Улучшение (одна попытка — `runAttempt`, генератор)

1. конструктор leg'ов с yield'ами прогресса («маршрут»);
2. каждая итерация:
   - градиент конечными разностями по `(t, angle, power)` каждого удара и
     свободным координатам битков;
   - координатный спуск;
   - раз в 2 итерации — веерная полировка каждой ноги (соседние углы/силы);
3. раз в 6 итераций, пока не решено — `rescueLegs`: перестройка
   непройденных ног по записанным кадрам лучшего состояния (прямой удар с
   гейтом `fwd > 0.4`, банк, переиспользование покоящихся битков, веера);
   улучшение принимается, stall сбрасывается;
4. на плато — Метрополис-отжиг по температуре;
5. после цикла — финальный `rescueLegs`.

Генератор отдаёт прогресс:
`{phase, iter, cost, best, solved, time, evals, note}` — UI крутит поиск
чанками `solver.run(20 мс)` через rAF и не блокирует страницу.

### 7.4. Ансамбль сидов (обязателен)

`solveGenerator` гоняет `cfg.attempts ?? 3` попытки с разными сидами
(базовый + два хэш-производных), первая может стартовать с
`cfg.seedPlan` (ручной план пользователя). Останавливается на первой
решившей. Лучшее состояние всех попыток хранится в `out.best`.

**Почему**: геометрия отдельных locked-ног для неудачного сида может вообще
не существовать в его конструкторе (биток за целью, перекрытая линия,
банк null). Больше итераций одного сида не помогают (проверено до 120
итераций) — нужен другой набор решений конструктора. На сложных маршрутах
у одиночного сида успехи ~50%; ансамбль из 3 даёт ~100%.

### 7.5. API

```js
const solver = new K.Solver(cfg, iters);   // iters ~22–26, attempts в cfg
while (!solver.done) solver.run(20);        // бюджет мс на чанк
solver.current  // → { state:{shots,cues}, res, cost }
solver.progress // → {phase,note,iter,evals,solved,time,best}
```

Рекомендуемые cfg планировщика: `fps:60, sub:3, attempts:3, iters:26`.
Решение детерминировано по `seed`.

### 7.6. Ориентировочный бюджет (60 Гц/sub3, 26 итер × 3 сида, seed 7)

| маршрут | расстановка | финиш, с | стенка, мс |

| zigzag | locked | 2.17 | ~1200 |
| arc | locked | 2.98 | ~9000 |
| rail | locked | 5.42 | ~1800 |
| zigzag | free | 4.23 | ~3200 |

## 8. Боты и живой режим

`LiveEngine(cfg)` (240 Гц физика, запись 60 Гц в собственный `Traj`):

- боты опрашиваются каждые 0.06 с; `botDecide(def, view)` возвращает
  `{angle, power, note}` или `null` (подождать);
- у каждого игрока кулдаун (человек 0.28 с, боты — `PLAYERS[i].cool`),
  `shotCount`, текущий `note`;
- `view` для ботов: `{balls, table, params, checkpoints, nextCp, t, maxPower,
  rollout(p,a,pw)}`; `rolloutCost` — быстрый прогон вперёд на `horizon ≈ 2.4 с`
  с тем же штрафом за непройденные точки;
- `need(view, distance)` — порог «стоит ли вообще вставать» (разные боты
  реагируют на разной дистанции).

Стратегии (`PLAYERS`):

| игрок | бот | поведение |
|---|---|---|
| КОМЕТА (жёлтый) | rusher | бьёт сразу как шар 1 в пределах досягаемости, короткий кулдаун, грубый прицел |
| ЦИРКУЛЬ (голубой) | geometer | ищет геометрию с отскоком от борта, точнее, думает дольше |
| ТИХОХОД (розовый) | tactician | ждёт почти полного покоя шара 1, бьёт редко и точно, малый джиттер |
| МАСТЕР (фиолетовый) | master | перебор вариантов через `rolloutCost`, без джиттера, самый дорогой |

Джиттер (`def.jitter`) имитирует ошибку руки. Человек выбирает любую из
4 позиций; бот на его позиции автоматически выключается.

Управление человеком: мышь задаёт прицел (рисуется ghost ball в точке
касания и линия, `castRay`), зажатие кнопки набирает силу (рампа 0→maxPower
за 0.85 с), отпускание — удар; пробел — старт/пауза, клавиши 1–4 —
смена позиции, точка — покадровый шаг на паузе.

## 9. Рендер

`makeView(table, cssW, cssH, pad)` даёт мировую→экранную аффинную шкалу
(`X,Y,L,unproject`), центр стола в контейнере, DPR-трансформ ставится
один раз при ресайзе.

- Стол: дерево с градиентом, лузы/рейлы, метки фетрового поля; лёгкий
  glow на финише.
- Траектории: сегменты раскладываются по **32 корзинам времени** и
  красятся единой шкалой `#fff4a3 → #ffb703 → #f4623a → #e0356f →
  #8e5bd6 → #2f9bd6` (старт→конец). Корзины — `Path2D`, которые строятся
  один раз на результат симуляции (или каждые несколько кадров в живом
  режиме) и переиспользуются покадрово; аллоцировать `Path2D` в каждом
  кадре запрещено. Шар 1 рисуется шире (2.8px), битки — 1.5px/α 0.6.
  Прореживание `stride=3`.
- Точки: заливка пройденной, пунктир непройденной, пульсирующее кольцо
  следующей, окно прохождения показывается на таймлайне.
- Удары: пунктирная стрелка от позиции битка **в момент t** (из кадров),
  длина головы `0.1 + 0.62·power/maxPower`; выбранная — сплошная и толще.
- Живой прицел: ghost ball, линия до первой цели/борта, дуга силы.

## 10. UI-планировщик

### Раскладка

- **Шапка**: переключатель план/вживую, расстановка замок/свободно,
  инструмент тащить/целиться, точки-индикаторы КП, рекорд.
- **Сцена**: canvas + нижняя шкала времени (play, шаг, текущее t, трек с
  градиентом времени, метки, скорости ¼/1/2/4×).
- **Правая колонка**, 3 вкладки:
  - *Расстановка*: пресеты маршрутов (зигзаг/дуга/борта/случайный), сброс
    ударов, копировать/вставить JSON; слайдеры физики (тение, упругости,
    радиус, массы, горизонт, макс. сила), кнопка «лёд», сброс;
  - *Команда*: карточки 4 игроков; добавление удара; у каждого удара три
    толчковых слайдера t/∠/F и удаление; в живом режиме — выбор позиции,
    тумблеры ботов, статусы и кнопки партии;
  - *Решатель*: решить/стоп, опции «сид из моих ударов» (`seedPlan`),
    «время — параметр» (timeMode), прогресс с фазой/числом оценок,
    статистика (стоимость, финиш, контакты, непройдено), чек-лист
    (контакт с шаром 1; каждая точка: t или ближайшая дистанция; финиш),
    журнал событий; после решения — «вернуть мои удары».

### Правка на холсте

- «тащить»: шар 1 — всегда; битки — только в free; точки — за центр
  (двигать) или за кромку (радиус);
- «целиться**: хэндлы стрелок: голова — угол и сила, колесо мыши — t;
- колесо над выбранной точкой меняет радиус;
- все правки помечают документ грязным; `runSim` перезапускается
  coalesce'ом на следующем rAF (дёшево: 60 Гц/sub4, ~10–20 мс).

### Прецизионный (толчковый) слайдер

Слайдер всегда центрирован в нуле и пружинит обратно; применяется
**относительная** поправка, логарифмическая по ходу:

```
f ∈ [-1;1] — положение рычага
Δ = sign(f) · scale · 0.0168 · (exp(4.8·|f|) − 1)
```

Калибровка при scale=1: ход 10% → ±0.01, ход 100% → ±2.0 (соответствует
примеру из ТЗ). Используемые scale: время 2.5 (с), угол 90 (градусы,
полный ход ≈ ±180°), сила 1, координаты/радиусы ~0.1. Двойной клик по
числу — ввод точного значения через prompt.

### Таймлайн

- трек раскрашен той же time-color шкалой;
- чёрточки — удары (цвет игрока) и зачёты точек; полупрозрачные полосы —
  окна нахождения в круге;
- в живом режиме скраббер блокируется во время бега и сам едет за t.

### Сериализация

`{ v:1, placement, doc }`, где `doc = {object, cues, checkpoints, shots,
physics, maxTime, maxPower}` (его же выдаёт `defaultDoc()`). Вставка
терпима к «голому» doc, проставляет id точкам/ударам, мёржит дефолтную
физику. Clipboard API под `file://` может быть запрещён — есть фолбэк
(выделение+execCommand для копирования, ручная вставка в textarea).

Рекорд: `localStorage['kribil-best-v1']` — карта `ключ(округлённые
координаты точек) → лучшее время`; пишется и в планировщике (решение),
и в живой партии.

## 11. Тесты

`npm test` → `node --test tests/*.test.js` (глоб в package.json
ограничивает прогон папкой tests, чтобы не подхватыть TS-тесты референсных
копий A/B/GLM).

Покрытие (`tests/engine.test.js`):

1. биток прямым ударом касается шара 1 (+ негатив: без удара контакта нет);
2. шар 1 проходит точку, окно и порядок времени верны (+ негатив: точка
   в стороне не зачитывается);
3. лобовая передача импульса равных масс;
4. сукно останавливает шары, на льду катятся;
5. отражение от борта (`cushion`) и возврат;
6. решатель проходит весь дефолтный маршрут в locked: финиш < горизонта,
   детерминизм по seed, битки не сдвинуты;
7. free-режим: финиш и хотя бы один переставленный биток;
8. живой режим: выстрел человека применяется, кулдаун держит второй,
   с выключенными ботами чужих ударов нет;
9. интерполяция `Traj.at` монотонна.

Ручной дымовой тест DOM (jsdom + стаб canvas/Path2D/ResizeObserver, без
браузера) держим вне репозитория; узкие места, которые он ловит:
инициализация панелей, переключение режимов, кадры без исключений.
